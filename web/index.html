A turnaround in five steps

Use the Rampside window, or type the same commands in the console. Rampside finds your stand and its jetway on its own, and follows what GSX or the sim do to the equipment.

  1. Dock the jetway

    The jetway comes to the forward door. On stands without one, call the stairs instead.

    jetway

  2. Board passengers

    Passengers per minute come from the aircraft profile. Passenger and bag weight go into the payload stations. Or load your SimBrief plan.

    board

  3. Refuel

    The truck arrives, fuel flows at the profile’s rate, wing tanks first, then center. Defueling works too.

    refuel 9000

  4. Close up

    Retract the jetway and disconnect ground power. Where Rampside controls the doors, it closes them first.

    jetway

  5. Push back

    Pick a direction by compass, or a pushback from your installed GSX airport profile. Release the brakes, steer tail left or tail right, and the crew calls the stop.

    push left

It refuses what a ground crew would refuse

Services know about each other. A command that would be unsafe on a real apron is turned down, with the reason.

  • NO PUSHEQUIPMENT CONNECTED

    No pushback while a jetway, stairs or ground power is connected, or boarding and refueling are still running.

  • NO PUSHDOORS OPEN

    On aircraft where Rampside controls the doors, every door has to be closed first.

  • NO BOARDINGNO ACCESS

    Boarding needs a jetway or stairs, and the last one can’t be removed while passengers are walking.

  • NO FUELENGINES RUNNING

    No refueling with engines running, unless the aircraft profile allows it.

Any aircraft, better with a profile

Rampside uses the sim’s own variables and ground equipment, so every aircraft gets the basics. A profile adds what’s specific to a type: seats, payload stations, fuel rate, tug geometry and timing.

Profiles are JSON files in the profiles folder. Rampside picks one when its match text appears in the aircraft title.

PMDG 737

Doors open and close with jetway, stairs and boarding. Stairs, ground power and chocks go through the CDU. Rampside talks to it only through the PMDG SDK, which it reads from your installation, so it follows PMDG updates on its own. 

// profiles/example-narrowbody.json
{
  "match": ["Airbus A320"],
  "icaoTypes": ["A320"],

  "passengers": {
    "capacity": 180,
    "boardingPerMinute": 18
  },
  "fuel": {
    "rateKgPerMinute": 600,
    "truckArrivalSeconds": 45
  },
  "pushback": {
    "wheelbaseMeters": 12.6,
    "speedMps": 1.2
  }
}

Uses what’s already on your disk

GSX airport profiles
Pushback targets and per-aircraft stop positions, read from your GSX folder at run time. Rampside never ships them.
SimBrief
Load passengers and cargo from your latest flight plan. Plans for another type or airport are flagged.
The scenery’s taxiways
Without a GSX profile, pushbacks are planned on the airport’s own taxiway graph, by compass direction.

Try it

Rampside is an early prototype. The service logic is tested against a simulated aircraft. What helps most now is flying it in MSFS 2024 and telling us what breaks.

Installer

The MSI brings everything it needs: the .NET runtime, SimConnect, aircraft profiles and crew voices. It isn’t code-signed yet, so Windows SmartScreen warns on first start.

Download the installer Latest release on GitHub, with release notes and the SHA-256 checksum.

From source

Needs the .NET 10 SDK. For the sim connection, also the MSFS 2024 SDK. Without it, Rampside runs against a fake aircraft.

# build and test
dotnet build Rampside.slnx
dotnet test

# try it without the sim
dotnet run --project src/Rampside.App -- --fake

# connect to MSFS 2024
dotnet run --project src/Rampside.App
